# 작업 세션 시작 목록과 작업별 사용량 시험

## 선택한 범위

작업 세션은 맡은 분야와 관계없는 것으로 확인된 스킬만 시작 목록에서 제외한다. 모르는 스킬과 안전·권한·검증 스킬은 남긴다. 분야를 알 수 없는 작업, 메인 세션, 확인 세션은 전체 목록을 쓴다. 프로젝트나 프로필이 스킬 목록을 따로 설정했다면 그 설정을 보존하려고 스킬 제외를 건너뛴다.

Codex의 전역 지침과 프로젝트 지침은 원래 위치에서 그대로 읽는다. 별도 설정 폴더를 만들면 인증 파일의 삭제·재생성 때 원본과 달라질 수 있어 사용하지 않는다. 메모리 훅이 추가로 읽는 상위 지침에서는 기존 `pane:skip`으로 표시한 메인 전용 부분만 생략한다. 메모리 목록은 분야가 명확한 링크만 생략하고 전체 인덱스 경로는 남긴다. 경계 표시가 잘못됐으면 해당 지침 전체를 유지한다.

연락 경로, 확인 세션을 여는 주체, 모델 선택, 샌드박스, 안전 훅은 이 시험에서 바꾸지 않는다. `init.sh`가 설치를 재현하며 설치기는 다른 훅을 보존한다.

훅 설치기는 기존 항목의 위치를 보존해 바꾸지 않은 훅의 신뢰 기록을 유지한다. 새로 추가하거나 바꾼 훅은 Codex에서 한 번 검토해야 한다. `pane-spawn`은 지시를 보내기 전에 `hooks need review` 창을 확인하면 실패를 알리고 빈 세션을 닫는다. 검토 창에 지시를 보내거나 훅을 자동 승인하지 않는다. 수동으로 연 Codex에서 `/hooks`로 변경을 확인한 뒤 같은 작업 번호로 다시 연다.

## 실행과 복구

`pane-spawn --task-type code|research|media|office|full`로 분야를 명시할 수 있다. 생략하면 보수적인 키워드 분류를 사용하고 모르는 작업은 `full`로 연다. 작업이 여러 분야에 걸치거나 빠진 스킬이 필요하면 새 세션을 `full`로 연다.

새 세션을 전체 목록으로 되돌리는 스위치는 하나다.

```sh
mkdir -p "${XDG_STATE_HOME:-$HOME/.local/state}/codex-startup"
printf 'full\n' > "${XDG_STATE_HOME:-$HOME/.local/state}/codex-startup/mode"
```

`full`을 `compact`로 바꾸면 다시 적용한다. 이미 열린 세션의 첫 입력은 바뀌지 않으므로 새 세션에서 확인한다. 작업 기록은 복구 뒤에도 계속 남겨 양쪽의 누락을 비교한다. 개인 경로·작업 기록·시험 기준 시각은 상태 폴더에만 저장하고 저장소에 넣지 않는다.

## 비교 전에 고정할 정의

- 첫 입력: 모델에 처음 전달한 전역·프로젝트 지침, 스킬 설명 목록, 메모리 훅의 추가 문맥. 로컬 프롬프트 검사는 글자·바이트 수이며 실제 API 토큰이나 비용과 구분한다.
- 세션: 공급자의 고유 세션 번호 하나. 작업마다 전용 세션을 사용한다. 같은 세션을 여러 작업에 쓰면 사용량 배분을 알 수 없어 누락으로 표시한다.
- 일 하나: 같은 요청에서 시작한 최상위 작업 번호 하나. 요청 시간으로 비교 구간을 정하고 실행·자식·재시도·확인 세션의 전체 사용량을 합친다. 구간이 끝난 뒤 완료된 작업은 당시 미완료였음을 따로 표시한다.
- 결과: 실행 세션이 명시한 `TASK_RESULT: pass|fail|unknown`. 빈 응답이나 단순 종료를 성공으로 보지 않는다. 자식의 결과는 부모의 완료를 대신하지 않는다. 결과 없음은 미완료와 명시적 미상을 함께 세되 두 종류를 따로 표시한다.
- 확인: 실행과 다른 세션이 실제 검증 후 명시한 `TASK_CHECK: pass|fail|unknown`. 확인 시도 전체가 분모이며 미상·확인 없음이 남으면 주요 실패율은 확정하지 않는다. 확인된 판정만의 비율과 관측 범위도 함께 제공한다.
- 다시 맡김: 같은 작업 번호로 다른 실행 세션을 여는 일. Sonnet에서 Opus로 바꿀 때는 전 모델·새 모델·이유를 명시한 `reassign` 이벤트를 남긴다. 기록 없이 두 모델이 관측되면 이유 미상으로 표시하고 비율을 확정하지 않는다.
- 토큰: 캐시 포함 합계와 캐시 적중분을 뺀 합계를 따로 합산한다. 자식·확인·재시도를 포함한다. 누락된 사용량을 0으로 채우지 않고 알려진 소계와 미상 총량을 구분한다. 이는 요금표를 적용한 청구액이 아니다.

## 같은 작업 번호로 이어 쓰기

`pane-spawn`이 요청과 실행을 기록하고 세션에 작업 번호를 전달한다. Codex 도구 셸이 환경변수를 제한해도 세션 번호로 부모 작업을 다시 찾는다. 자동 확인 전달은 기존 연락 경로를 유지하며 작업 번호만 함께 보낸다. 명시적으로 확인하거나 다시 맡길 때는 원래 `--job-id`를 재사용한다.

```sh
# JOB must be the original ID, not a newly generated ID for the retry.
python3 tools/agent-hooks/task-ledger.py record reassign \
  --job-id "$JOB" --from-model sonnet --model opus --reason 'verification failed'
pane-spawn --kind claude --opus --job-id "$JOB" 'Retry' 'Repeat the original task and verify the result'
```

메인 세션만 기존 절차에 따라 `--check --job-id "$JOB"`를 사용한다. 기록 명령을 쓰는 데 배포·외부 전송 권한이 생기지는 않는다. 기록기는 프롬프트나 응답 본문을 저장하지 않는다.

```sh
python3 tools/agent-hooks/task-ledger.py report \
  --since '2026-01-01T12:00:00+09:00' --until '2026-01-02T12:00:00+09:00' \
  --codex-root "$HOME/.codex"
```

도입 전 요청 번호가 없으면 과거의 작업당 사용량과 확인·재배정 비율을 복원할 수 없다. 연결되지 않은 세션 수와 누락을 공개하고 개선 효과를 단정하지 않는다. 비교는 같은 길이의 구간과 같은 작업 정의를 사용하며 작업 수·종류와 검증 범위가 달라졌는지도 함께 본다.
