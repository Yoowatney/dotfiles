# Claude 시작 문맥 관리

작업 칸과 메인 칸은 실행할 때 필요한 기능을 선택한다. 프로파일은
[시작 래퍼](../scripts/claude-online)가 CLI 설정으로 전달한다. 따라서 같은
프로세스 안에서 `/clear`를 실행해도 설정이 유지된다. 이미 실행 중인
프로세스에는 이 인자가 없으므로 처음 적용할 때 한 번 재시작해야 한다.

작업 칸의 역할은 [pane-spawn](../tools/agent-hooks/pane-spawn)이 전달하고,
메인 칸은 저장된 terminal ID로 확인한다. 명시적인 `CLAUDE_STARTUP_ROLE`이
자동 감지보다 우선하므로 작업 칸을 메인으로 바꾼 경우에는 역할도 바꾸고
다시 실행해야 한다. 모든 기능이 필요한 작업은 실행 전에
`CLAUDE_STARTUP_PROFILE=full`을 지정한다.

제외 기능의 근거는 적용 당시의 사용 기록에서 확인해야 한다. 짧은 기간에
호출이 없었다는 사실만으로 앞으로도 쓰지 않는다고 판단할 수는 없다.
실제 제외 목록은 [프로파일](../tools/claude/startup-profile.json)을 기준으로 한다.

설정 소스를 제한하거나 `--bare`로 실행하면 안전 훅과 규칙도 빠질 수 있으므로
사용하지 않는다. 시작 프로파일에는 훅·권한·규칙을 덮어쓰는 설정을 넣지 않는다.
권한은 `deny`만 넣는다. 거부 규칙은 다른 설정의 규칙과 합쳐지기만 하므로 권한을
넓히지 않는다. 작업 칸은 요유가 보지 않으므로 질문 창(`AskUserQuestion`)을 띄우면
그대로 멈춘다. 그래서 작업 칸에서는 질문 창을 막는다.

호출하는 쪽이 `--settings`를 한 번 더 넘기면 래퍼의 프로파일이 통째로 바뀐다
(2026-11-06 확인). 칸에 설정을 더 줘야 하면 프로파일에 넣는다.

## 리드 밑 칸의 규칙 파일 (api#1031)

작업 칸과 확인 칸은 리드에게만 보고하므로, 리드와 메인 칸만 쓰는 규칙(칸 관리,
요유에게 쓰는 보고 형식, `/clear` 인계)이 필요 없다. 이런 구간은 원본 규칙 파일에
`<!-- pane:skip -->`와 `<!-- /pane:skip -->` 표시로 감싼다. 프로파일의 `paneRules`에
적힌 파일은 래퍼가 표시한 구간을 뺀 사본을 만들어 `--append-system-prompt-file`로
넘기고, 원본은 `claudeMdExcludes`로 뺀다. `<!-- pane: … -->` 한 줄은 사본에서만
보이는 안내가 된다. Claude는 자기가 읽는 규칙 파일의 HTML 주석을 모델에 보내지
않으므로, 메인 칸과 요유가 손으로 연 세션의 시작 글은 표시 때문에 달라지지 않는다.
원본이 유일한 정본이고 사본은 실행할 때마다 원본에서 다시 만든다.

표시는 칸이 정말 쓰지 않는 구간에만 단다. 칸이 꼭 지켜야 하는 규칙은 훅이 지켜야
한다. 2026-11-06에 뺀 구간과 그 규칙을 지키는 장치는 다음과 같다.
- 탭 이름, 다른 세션에 말 전하기, 👑·🫡 표시, 탭 표시: `pane-label`과 launchd가 처리한다.
- 칸 열기: `herdr agent start` 등은 Bash 훅이 막고, 사본에 `pane-spawn` 안내가 한 줄 남는다.
- 요유에게 묻지 않기, 보고 형식: `pane-spawn`이 칸마다 안내를 붙이고, 질문 창은 막는다.
- 보고를 리드에게 보내기: Stop 훅 `auto-tab-close.py`가 보낸다.
- 회고 KPI 절과 ambient 설명: 사본에 원본 위치를 가리키는 안내가 남는다.

## 2026-11-06에 뺀 기능과 근거

10/31~11/06 작업 칸 286개와 확인 칸 133개의 기록을 세어 정했다.
- MCP: rea와 obsidian은 호출이 0번이라 뺐다. claude.ai 연결(Gmail, 캘린더, 드라이브,
  Notion, Claude Docs)은 Claude Docs 호출 2번 말고는 쓰지 않아 뺐다. Amplitude(칸 5개),
  notion-token(칸 3개), Slack은 쓰고 있어서 남겼다.
- 플러그인: hyperframes, watch, ralph-loop, claude-hud, skill-creator는 칸에서 쓴 적이 없다.
  플러그인 스킬은 `skillOverrides`로 끌 수 없어서 플러그인째 끈다.
- 스킬: 가계부, 이력서 패널, 영상 자막, 역분석, 메인 칸 전용, claude.ai의 브라우저·문서
  스킬처럼 칸에서 한 번도 부르지 않은 스킬을 `skillOverrides`로 껐다. 스킬 설명은
  정해진 예산 안에서 나오므로, 몇 개를 꺼도 남은 스킬의 설명이 길어져 합계는 조금만 준다.
- 메모리 목차는 배포·Slack·비밀값 규칙이 많아서 남겼다. Artifact는 클라 핸드오프
  페이지를 칸이 발행하므로 남겼다.

되돌리기: 프로파일에서 `roles.worker`의 해당 키를 지우면 다음에 여는 칸부터 원래대로
돌아간다. 규칙 파일의 표시는 지우지 않아도 된다(`paneRules`가 없으면 쓰이지 않는다).

긴 인계와 보드 글은 원문을 파일로 보관하고 시작 문맥에는 읽을 위치를 넣는다.
이는 첫 요청에서 원문을 미루는 방법이다. 원문을 읽은 다음 요청부터는 그 글이
다시 문맥에 들어오므로, 계속 절약되는 토큰으로 계산하면 안 된다.
보드용 래퍼는 비공개 SessionStart 설정에서만 연결하며 안전 훅에는 연결하지 않는다.

측정할 때는 usage의 일반 입력·캐시 생성 입력·캐시 읽기 입력을 합한다.
같은 assistant message ID의 스트리밍 조각은 한 요청으로 센다. 구성별 다른
토크나이저의 추정치는 이 합계와 일치하지 않으며 비율로 보정하지 않는다.
시작 도중 연결된 MCP 목록도 비교해야 한다. 연결 지연으로 빠진 도구를
프로파일의 절감 효과에 포함하면 안 된다.
