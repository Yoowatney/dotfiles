# 일반 부하 세션의 실행기 자동 선택

이 기능은 `pane-spawn --kind auto`로 여는 일반 부하 세션에만 적용한다.
새 설치의 정책은 `quota-aware`다. 이 브랜치의 커밋만으로 기존 설치가 바뀌지는 않는다.
운영 설치와 다른 기기 동기화는 리뷰 이후 별도로 진행한다.
설정 검사에는 Python 3.11 이상이 필요하다. 저장소의 mise 설정이 이 버전을 설치한다.
`codex-only` 복구는 셸에서 먼저 처리하므로 Python과 결정 로그에 의존하지 않는다.

## 운영 판단

사용량을 아끼려고 결제 방식이나 계정을 바꾸지 않는다.
최근 사용량과 구독 결제 상태를 확인할 수 있는 실행기만 자동 선택한다.
Codex 사용량이나 결제 상태를 모르면 자동 시작을 거부한다.
Claude 사용량이나 결제 상태를 모르면 Claude를 제외하고, 조건을 만족하는 Codex를 유지한다.
Codex도 조건을 만족하지 못하면 시작을 거부한다.
둘 다 남겨 둘 사용량에 도달하면 시작을 거부한다.
한 실행기를 골랐다가 시작에 실패해도 다른 실행기로 재시도하지 않는다.

구체적인 선택 기준은 [agent-quota](../tools/agent-hooks/agent-quota)의 `normalize`와 `select`가 기준이다.
이 차이는 Claude 상태가 불명확하면 전환하지 않고 기존 Codex를 유지한다는 설계를 따른다.
Codex 자체의 사용량과 결제 상태는 확인되어야 한다.
자동 선택한 Claude에는 Sonnet 5.5와 high를 기본으로 준다.
확인 세션, 명시적 실행기, `--why`, 직접 지정한 모델·강도는 기존 경로를 유지한다.
`--kind`를 생략한 기존 Claude 경로도 그대로 둔다.
`--` 뒤에 실행기 인자를 주면 기존 Codex를 유지한다. 같은 인자를 Claude가 다른 뜻으로 읽을 수 있기 때문이다.
집맥의 `ambient-runner`도 기존 Codex를 유지한다. Claude에는 같은 sandbox 보호가 없기 때문이다.
사용량 조회가 6초를 넘으면 경고 한 줄을 남기고 기존 Codex로 시작한다.
이 시간 초과 복구는 새 사용량 검사를 건너뛴다. 사용량을 읽었으나 조건을 만족하지 못한 경우에는 시작을 거부한다.

## 결제 차단의 한계

이 구현은 **시작 전에 로컬 자료를 확인하는 검사**다. 실행 중 지출 한도를 강제하는 기능은 아니다.
Codex는 최근 기록에서 유료 크레딧이 없다고 확인되어야 한다.
Claude는 현재 계정의 `hasExtraUsageEnabled`가 명시적으로 false여야 한다.
값이 없거나 추가 사용이 켜져 있으면 해당 실행기를 제외한다.
API 키, 외부 공급자, 프로젝트 설정으로 결제를 바꾸는 경로도 제외한다.

Claude의 계정 메타데이터가 서버 설정과 언제나 같다는 보장은 확인하지 못했다.
다른 세션이나 사람이 실행 후 크레딧을 사거나 결제 설정을 바꿀 수도 있다.
로컬 검사만으로 이런 변경을 막을 수는 없다.
따라서 이 구현을 “실행 중 추가 결제가 절대로 발생하지 않음”으로 승인해서는 안 된다.
독립 리뷰에서 이 조건을 먼저 판단해야 한다.
실제 계정의 결제 상태와 실제 세션 시작은 이번 변경에서 검증하지 않았다.

공식 설명: [Claude Code 비용 관리](https://code.claude.com/docs/en/costs),
[OpenAI 크레딧 사용](https://openai.com/index/beyond-rate-limits/).
명시적 실행기·직접 모델 지정·확인 세션·`codex-only` 복구 경로에는 새 검사를 적용하지 않는다.

## 사용량이 없을 때

Claude 상태줄은 공식 `rate_limits` 입력을 현재 계정과 기기에 묶어 저장한다.
실제 assistant 응답이 새로 있어야 관측 시각을 바꾼다.
상태줄을 다시 그린 것만으로 오래된 사용량을 최신으로 바꾸지 않는다.
자료가 없으면 평소 사용하는 세션에서 실제 응답이 발생한 뒤 다시 시도한다.
시작을 허용하려고 캐시 시각이나 결제 상태를 직접 고치지 않는다.

상태줄 수집이 실패해도 기존 상태줄은 계속 표시한다.
상태줄의 오래된 기록 표시는 자동 시작을 허용하는 근거가 아니다.
상태줄은 최근 수정된 파일 5개에서 이벤트 시각을 비교한다. 자동 선택기는 최근 기록 전체를 확인한다.
따라서 상태줄 표시는 자동 선택 결과와 다를 수 있다. 상태줄 때문에 매번 전체 기록을 읽지는 않는다.
예전 timestamp 없는 표시 형식은 상태줄에서만 지원한다.

## 앞 검증의 정정

수정 전에는 이 기기의 현재 기록에서 자동 시작을 거부했다. 미래 기록까지 포함해 “항상 거부”한다고 단정하지 않는다.
실제 기록에는 주간 창만 있었다. 300분 창이 없는 경우에는 주간 창만으로 판단한다.
스캔 도중 생기는 기록을 고려해 관측 시각이 비교 시각보다 최대 5초 늦어도 허용한다.

프로젝트의 `.envrc` 같은 환경 파일은 새 셸에서 환경을 바꿀 수 있다.
현재 셸에서 API 접속을 바꾸는 값이 없더라도 새 셸의 환경까지 보장하지 않는다.

## 정책 하나로 복구

현재 기기에서 다음 명령으로 기존 Codex 고정 선택으로 되돌린다.

```bash
quota_state="${XDG_STATE_HOME:-$HOME/.local/state}/agent-quota"
mkdir -p "$quota_state"
chmod 700 "$quota_state"
printf '%s\n' codex-only > "$quota_state/policy"
```

다음 자동 세션부터 적용하며 이미 실행 중인 세션은 바꾸지 않는다.
이 복구 정책은 기존 동작처럼 새 사용량 검사도 건너뛴다.
자동 선택을 다시 사용하려면 같은 파일에 `quota-aware`를 쓴다.
오타가 있는 정책 값은 시작을 거부한다.
로컬 정책 파일이 없으면 설치된 `agent-quota-policy`를 읽는다.

## 확인할 자료

선택 이유는 시작 시 stderr에 표시한다.
관측과 결정 로그는 `${XDG_STATE_HOME:-$HOME/.local/state}/agent-quota/`에 저장한다.
계정 식별자는 해시로 남기고 인증 토큰은 저장하지 않는다.
결정 로그를 쓸 수 없어도 자동 시작을 거부한다.
단, 셸에서 먼저 처리하는 복구 정책과 시간 초과 복구는 로그를 요구하지 않는다.
로그에는 정책, 사용률, 관측·리셋 시각, 거부 이유가 들어간다.
결정 로그는 최근 완전한 행만 남겨 최대 1 MiB로 제한한다. 동시에 기록해도 같은 잠금을 사용한다.
다른 곳에 공유하기 전에는 계정 사용량이라는 점을 고려한다.

회귀 검증 명령:

```bash
bash tools/agent-hooks/agent-quota.test.sh
bash tools/agent-hooks/pane-spawn.test.sh
bash tools/claude/statusline-command.test.sh
```

테스트는 합성 계정과 임시 HOME을 사용한다.
실제 계정이나 실제 부하 세션을 사용했다는 근거가 되지는 않는다.
