# Actions 수동 실행 차단 구현 계획

> 실행 방법: 이 세션에서 직접 구현하고 로컬 시험을 거친 뒤 PR까지만 만든다.

**목표:** Claude와 Codex가 확인만을 위해 Actions 실행을 추가하는 실수를 Bash 앞에서 막는다.

**설계:** 이미 두 실행기에 등록된 공통 안전 훅에서 새 검사를 부른다.
새 등록 항목은 Codex의 신뢰 승인을 기다리고, 열린 세션에 바로 적용되지 않아 선택하지 않았다.
공통 훅의 기존 거절을 새 예외로 풀지 않는다.

**기술:** Python 표준 라이브러리, 기존 PreToolUse JSON 형식, unittest.

## 범위와 제약

- 직접 실행하는 수동 시작·재실행·활성화 명령과 같은 REST 쓰기를 거절한다.
- `ACTIONS_RUN_REASON`에 직접 적은 8자 이상의 이유를 해당 명령 앞에 붙이면 이 검사만 통과한다.
- 상속된 환경 변수, 빈 이유, 다른 명령에 붙인 이유는 예외로 인정하지 않는다.
- 릴리스 생성, 배포 스크립트 호출, PR push, 조회와 도움말은 통과한다.
- 셸 문자열은 실행하지 않고 분석한다. 임의의 스크립트 내부, alias, 동적으로 조합한 명령은 이 검사의 범위 밖이다.
- 원래 체크아웃과 실행기의 실제 설정은 변경하지 않는다. worktree의 후보 훅으로 로컬 검증한다.
- Actions 실행으로 검증하지 않는다. PR을 머지하지 않는다.

## 구현과 시험

- [x] 기존 공통 훅과 두 실행기의 등록 경로를 읽는다.
- [x] 기존 훅에 거절 명령을 입력하는 시험을 먼저 추가하고 거절하지 않는 실패를 확인한다.
- [x] `tools/agent-hooks/actions-run-guard.py`에 명령별 이유와 Actions 쓰기 검사를 구현한다.
- [x] `tools/claude/hooks/gcp-account-guard.py`의 기존 검사 연결부에 추가한다.
- [x] `tools/agent-hooks/actions-run-guard.test.py`로 차단·예외·제외 동작을 검증한다.
- [x] 옵션 위치, 암시적 POST, 명령 치환, 단순 문자열과 주석을 회귀 시험에 넣는다.
- [x] 두 실행기의 실제 등록 명령에서 후보 경로만 바꾸어 deny/allow JSON을 로컬에서 확인한다.
- [x] 기존 안전 훅과 에이전트 훅의 로컬 unittest 모음도 실행한다.
- [x] 변경과 검증 근거를 검토한다. PR 생성은 push 뒤 별도로 실행한다.

## 검토할 경계

- 이유가 한 명령에서 다음 명령으로 넘어가지 않아야 한다.
- `gh api`의 필드나 `--input`은 명시적인 GET이 없으면 POST로 판단해야 한다.
- 인용한 명령 설명은 차단하지 않고, 실제 명령 치환 안의 실행은 차단해야 한다.
- 릴리스와 push를 차단해서 기존 배포 경로를 막지 않아야 한다.
- 후보 훅의 통과를 실제 설정 설치나 대화형 세션 검증으로 보고하지 않아야 한다.

## 적용과 되돌리기

PR을 머지하기 전에는 실제 실행기 동작이 바뀌지 않는다.
적용 뒤 되돌리려면 이 PR을 revert한다. 기존 훅 등록은 그대로 사용하므로 별도 설정 정리는 필요 없다.
