# 맥 설정 차이 매일 점검 설계

2026-11-19 · 요청: 요유 · 상태: 검토 대기

## 왜 필요한가

휴대맥에서는 한글을 치다가 Caps Lock+A, Caps Lock+E를 누르면 커서가 움직이지 않았다. 원인은 입력기 차이였다. 세션맥은 구름 입력기를 쓰는데, 휴대맥만 macOS 기본 한글 입력기를 쓰고 있었다. dotfiles는 구름 입력기를 설치한다. 그런데 입력 소스로 켜는 `scripts/setup-gureum.sh`는 `defaults write` 뒤에 로그아웃해야 적용된다. 그래서 휴대맥에는 이 설정이 적용되지 않았다. `verify.sh`도 입력 소스를 검사하지 않아서 차이가 드러나지 않았다. 결국 요유가 증상을 하나씩 짚은 뒤에야 원인을 찾았다.

같은 날 두 맥의 설정값 541개를 비교했다. 그 결과 차이가 세 가지 더 나왔다.

- 휴대맥에는 AlDente가 설치되어 있지 않다. Brewfile에는 들어 있다.
- Snap의 앱 단축키 목록(`apps`)과 Dock의 앱 목록(`persistent-apps`)이 두 맥에서 다르다.
- 세션맥에는 `macos/defaults.sh`의 TextEdit 설정 3개가 적용되어 있지 않다.

이 작업의 목표는 맥 사이의 설정 차이를 요유가 짚기 전에 드러내는 것이다.

## 목표

- 입력 소스 설정을 로그아웃 없이 명령으로 적용한다. `init.sh`가 이 명령을 실행한다.
- `verify.sh`가 다음 항목을 검사한다. 입력 소스, `macos/defaults.sh`에 적힌 값, Brewfile 앱의 설치 여부, Snap 앱 목록, Dock 앱 목록이다.
- 세션맥이 매일 세 맥(세션맥, 집맥, 휴대맥)에서 `verify.sh`를 실행한다. 새로 실패한 검사가 있으면 메인 알림함에 알림을 하나 넣는다.
- 이번에 찾은 차이를 맞춘다. 휴대맥에 AlDente를 설치하고, Snap과 Dock은 세션맥 값으로 맞춘다. 세션맥에는 `macos/defaults.sh`를 다시 적용한다.

## 하지 않는 것

- 점검은 설정을 고치지 않고 알리기만 한다. 요유가 쓰고 있는 맥의 입력기나 Dock이 갑자기 바뀌면 안 되기 때문이다.
- 창 위치, 업데이트 확인 시각, 사용 횟수처럼 쓰는 동안 바뀌는 값은 검사하지 않는다.
- API 키가 들어 있을 수 있는 앱 설정(Easydict 등)은 검사하지 않는다.
- Slack으로는 보내지 않는다.

## 실패로 보는 경우

아래 경우는 점검이 동작하더라도 실패로 본다.

- 같은 차이로 매일 알림이 반복된다. 같은 실패가 이어지는 동안에는 알림을 한 번만 보내야 한다.
- 휴대맥이 잠자기 상태여서 접속하지 못했는데, 이것을 설정 차이로 알린다.
- 알림이나 로그에 설정값 원문이나 비밀값이 들어간다. 알림에는 맥 이름과 검사 이름만 넣는다.

## 제약

- dotfiles는 공개 저장소다. 접속 주소와 회사 정보는 저장소에 넣지 않는다. 점검 대상은 세션맥에 이미 있는 설정 파일에서 읽는다. 집맥 주소는 `~/.config/herdr/remote-host`에, 휴대맥 주소는 `~/.config/munice/portable-host`에 있다.
- 공유 설정은 세션맥에서만 바꾼다. 매일 도는 잡은 세션맥에만 설치한다.
- 정기 잡은 기존 정기 작업 감시 래퍼로 감싼다(`docs/scheduled-job-health.md`). 잡이 두 번 연속 실패하면 이 래퍼가 따로 알린다.
- 스크립트는 macOS 기본 Python(`/usr/bin/python3`)과 bash로만 만든다. 입력 소스는 Carbon의 TIS API로만 바꿀 수 있다. 그래서 이 도구만 Swift로 만들고, 맥마다 `swiftc`로 컴파일한다.
- 세 맥의 `~/.dotfiles`는 기존 동기화(`sync-home.sh`)가 3분마다 같은 커밋으로 맞춘다. 그래서 세 맥은 같은 `verify.sh`를 실행한다.

## 검토한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. 맥마다 `verify.sh` 검사만 늘린다 | 만들 것이 적다 | 누군가 `verify.sh`를 실행해야만 차이가 보인다 |
| B. A에 세션맥의 매일 점검을 더한다 | 요유가 짚지 않아도 알림이 온다 | 만들 것이 늘고, 잠자기 상태인 맥은 그날 건너뛴다 |
| C. 동기화할 때마다 설정을 자동으로 적용한다 | 차이가 저절로 사라진다 | 쓰는 중에 입력기나 Dock이 바뀔 수 있다 |

요유가 2026-11-19에 B를 골랐다. C는 사용 중인 맥을 예고 없이 바꾸기 때문에 제외했다.

## 구성

### 1. 입력 소스 도구

- `macos/input-sources/input-sources.swift`에 명령 세 개를 둔다.
  - `list`: 켜진 키보드 입력 소스와 현재 입력 소스를 출력한다.
  - `check`: 원하는 목록과 다르면 차이를 출력하고 종료 코드 1로 끝난다.
  - `apply`: 원하는 입력 소스를 등록해서 켜고 선택한다. 그다음 목록에 없는 키보드 입력 소스를 끈다.
- 원하는 목록은 `macos/input-sources/enabled.txt`에 적는다. 내용은 구름 두벌식(`org.youknowone.inputmethod.Gureum.han2`)과 구름 로마자(`org.youknowone.inputmethod.Gureum.system`)다. 처음 선택할 입력 소스는 목록의 첫 줄이다.
- 2026-11-19에 휴대맥에서 확인한 점이 있다. 구름 입력기는 켠 직후 선택하면 `-50`(paramErr)으로 실패했고, 몇 초 뒤에는 성공했다. 그래서 `apply`는 선택을 몇 번 다시 시도한다.
- `scripts/input-sources.sh`가 도구를 컴파일하고 `list`, `check`, `apply`를 실행한다. 이 스크립트가 `scripts/setup-gureum.sh`를 대신한다. `init.sh`는 지금 구름 입력기를 열고 안내 문구만 출력하는데, 그 자리에서 이 스크립트를 실행한다.

### 2. `verify.sh`에 더하는 검사

새 검사는 실패하면 ❌로 표시한다.

- **입력 소스:** 입력 소스 도구의 `check` 결과를 쓴다.
- **`macos/defaults.sh` 값:** `defaults write <도메인> <키> -bool|-int|-float|-string <값>` 형식의 줄을 읽고, 실제 값과 비교한다. 단축키 묶음처럼 `-dict-add`로 쓰는 값은 이번에 F18 한/영 단축키(심볼릭 단축키 60번) 하나만 따로 검사한다.
- **Brewfile 앱:** Brewfile의 cask와 mas 앱이 설치되어 있는지 검사한다.
- **Snap과 Dock:** `macos/snap/snap.xml`의 `apps`, `macos/dock/dock.xml`의 `persistent-apps`에서 앱 번들 ID 목록만 뽑아 실제 목록과 비교한다. 창 위치 같은 나머지 키는 비교하지 않는다. 두 xml은 세션맥의 현재 값으로 다시 저장한다.
- `verify.sh`는 마지막에 실패한 검사 이름을 한 줄에 하나씩 `VERIFY-FAIL <검사 이름>` 형식으로 출력한다. 원격 점검은 이 줄만 읽는다. 사람이 읽는 기존 출력은 그대로 둔다.

### 3. 세션맥의 매일 점검

- `tools/settings-drift/settings-drift.py`는 세션맥 자신과 두 점검 대상에서 `bash ~/.dotfiles/verify.sh`를 실행한다. 원격 맥은 ssh로 실행한다.
- 맥마다 `VERIFY-FAIL` 줄을 모아 (맥, 검사) 묶음을 만든다. 직전 결과에 없던 묶음이 생기면 메인 알림함(`tools/agent-hooks/main-alert-inbox.py`)에 알림을 하나 넣는다. 실패가 해결되면 알림 없이 기록만 고친다.
- 접속에 실패한 맥은 그날 건너뛰고 로그만 남긴다. 다만 7일 동안 한 번도 점검하지 못한 맥이 있으면 그 사실을 한 번 알린다(설계자의 판단).
- `verify.sh` 자체가 실행되지 않은 경우(종료 코드 127, 파일 없음)는 그 맥의 `점검 실행 실패`로 알린다.
- 상태는 `~/.local/state/settings-drift/`에 저장한다. 맥마다 마지막으로 점검에 성공한 시각과 실패 묶음만 저장하고, 출력 원문은 저장하지 않는다.
- `tools/claude/com.yoyoo.settings-drift.plist`가 하루에 한 번 실행한다. 기존 정기 잡 설치 방식을 따른다.

### 4. 이번에 맞출 것 (머지 뒤)

- 휴대맥에 AlDente를 설치한다. 첫 실행 때 관리자 승인을 한 번 해야 하는데, 이 승인은 요유가 한다.
- 세션맥 값으로 다시 저장한 Snap과 Dock 설정을 휴대맥과 집맥에 적용한다.
- 세션맥에서 `macos/defaults.sh`를 다시 적용한다.
- 첫 점검에서 세션맥의 `gh authenticated`가 ❌로 나온다. 이 결과는 알림으로 받은 뒤 따로 판단한다.

## 검증

- 단위 시험: `VERIFY-FAIL` 줄 읽기, 알림 중복 방지, 접속 실패 처리, 7일 미점검 알림, `macos/defaults.sh` 줄 읽기.
- 실패 흐름: 원하지 않는 입력 소스를 켠 상태에서 `check`가 1로 끝나는지 확인한다. 원격 접속이 실패하면 알림이 생기지 않는지, 같은 실패가 이틀 이어지면 알림이 한 번만 생기는지도 확인한다.
- 실제 실행: 세 맥에서 점검을 한 번 실행하고, 알림 내용에 맥 이름과 검사 이름만 들어 있는지 확인한다.

## 구현할 때 정할 것

파일 안의 함수 구성, 상태 파일 형식, 매일 실행하는 시각, 알림 문구.
