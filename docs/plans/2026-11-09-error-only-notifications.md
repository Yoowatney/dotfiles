# 에러만 터미널에 남기는 구현 계획

**목표:** 완료·입력 대기·상태 알림을 끄고 전달 실패와 담당 세션 부재 경고는 보존한다. Slack으로 옮기지 않는다.

**구조:** herdr 0.9.0의 전체 알림을 끄고 기존 에러 발신자가 별도 영속 대기열을 사용한다. 회사맥의 실제 herdr 클라이언트 TTY 하나로 OSC 9를 보내며, 집맥의 미전달 경고는 기존 원격 호스트 연결로 회사맥에 가져온다. 전달받은 UUID와 전송한 UUID를 보관해 재시도 중 중복을 막는다.

**제약:** 전역 설정은 회사맥에서 고친 뒤 기존 동기화로 배포한다. Slack 글은 쓰지 않는다. 다른 세션의 미커밋 변경은 보존한다.

- [ ] 네 상태 알림 훅: 실제 훅을 실행하는 실패 검사 후 완료·입력 대기 알림을 끈다. workers 생략 로그를 보존한다.
- [ ] 에러 게이트웨이: 실제 PTY 프레임, 수신자 없음, 쓰기 실패, 중복 수입, 동시 저장과 손상 파일 보존을 검사한다.
- [ ] 기존 에러 발신자 세 곳을 연결하고 정상적인 새벽 작업 생략은 로그만 남긴다. 기존 전달 실패·담당 없음 재시도 검사를 통과한다.
- [ ] 원격 대기열 가져오기: 수입 성공 뒤에만 원본을 확인 처리한다. SSH 실패·수입 실패·확인 실패와 재시도 중복을 검사한다.
- [ ] 독립 검토 후 회사맥·집맥의 현재 및 새 클라이언트에서 정상 알림 차단과 에러 프레임을 검증한다. 커밋·push 및 되돌리는 명령을 보고서에 남긴다.

**검토 초점:** 알림 API의 shown 값은 화면 표시 증거가 아니다. 터미널이 없으면 경고를 버리지 않는다. 집맥의 기존 moved 보고 전달은 유지한다. 원격 확인에 실패하면 같은 UUID를 다시 가져와도 재전송하지 않는다. 클라이언트 설정을 다시 읽혀 현재 열린 세션에도 반영한다.
