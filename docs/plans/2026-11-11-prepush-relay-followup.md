# 사전 검사와 메인 세션 전달 후속 작업

요청한 순서대로 진행한다. 실패를 가리기 위해 시간 제한을 늘리지 않는다. 공개 저장소에는 회사 정보와 전달 글 내용을 넣지 않는다.

1. 이전 사전 검사 실패 13건을 로그와 현재 코드에서 분류한다. 같은 커밋의 전체 검사를 실행하고, 권한 제한과 부하를 실제 결함과 구분한다. 실제 결함은 재현 시험을 먼저 만든 뒤 고친다.
   - 검증: 실패별 근거, 개별 재현 결과, 전체 사전 검사 결과를 남긴다.
2. 세션 기록 검사 안내 문구 커밋을 원격에 올린다.
   - 검증: 사전 검사 통과와 원격 커밋 포함 여부를 확인한다.
3. 기존 PR과 두 후속 브랜치의 검사 상태를 읽고 PR 생성 여부를 판단한다. 병합하지 않는다.
   - 검증: 원격 PR 상태, 검사 결과, 브랜치 차이를 확인한다.
4. 전달되지 않은 글은 비공개 파일에서 읽고 다시 보낼 필요만 판단한다. 보고에 내용을 옮기지 않는다.
   - 검증: 파일 메타데이터와 전달 기록을 대조한다.
5. 메인 초안 보존 브랜치 위에서 큰 셸 입력 리다이렉션을 없애고 전달 도구 밖에서 막힘을 알린다.
   - 검증: 512바이트를 넘는 입력, 정상 전달, 실패 알림과 기존 회귀 시험을 실행한다.
6. 남은 시험 프로세스의 명령과 부모·자식을 확인하고 시험 프로세스로 확인된 것만 정리한다.
   - 검증: 정리 전후 프로세스 정보를 남긴다. 관련 없는 지정 PID는 건드리지 않는다.

진행 기록과 실행 로그는 저장소 밖의 `/tmp/codex/api1139-followup/`에 남긴다. 마지막에 별도 에이전트가 결론과 변경을 반박 검토한다.
