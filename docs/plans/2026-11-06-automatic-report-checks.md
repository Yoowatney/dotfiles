# 메인 칸 보고 확인 자동화

- 일 칸의 결과를 저장한 뒤 코드가 확인 칸을 열고, 원 보고와 확인 결과를 한 번에 전달한다.
- 요유 몫, 질문, 결정 요청, 확인할 결과가 없는 보고와 확인 칸 시작 실패는 즉시 전달한다.
- 메인 칸이 직접 연 일 칸에만 적용한다. 다른 리드와 집 일 칸의 전달 방식은 유지한다.
- 확인 종류는 보고의 네트워크·프로세스 명령어 단어로 정한다. 해당 단어가 있으면 Claude, 없으면 기존 자동 선택을 쓴다.
- 보고별 상태를 먼저 저장하고 확인 칸을 열어 빠른 확인 완료와 중복 Stop에도 원 보고가 누락되거나 재전달되지 않게 한다.

검증은 실패 시험을 먼저 쓰고 구현과 관련 hook 시험을 진행한다.
시험용 받는 칸을 둔 실제 workers 시험과 독립 검토를 거쳐 origin/main 위로 rebase하고 커밋한다.

검증 결과:
- 전달 흐름 회귀 시험 14개를 통과했다. 결과 전달, 즉시 전달, 확인 칸 시작·전달 실패, 중복 종료, 다른 리드·집맥 경로를 확인했다.
- 실제 workers 서버에서 임시 일 칸이 보고하자 확인 칸이 자동으로 열렸다. 확인 칸이 파일 내용과 프로세스 조회를 직접 확인했고 시험용 받는 칸에 합친 보고 한 글이 도착했다. 실제 메인 칸에는 보내지 않았고 임시 칸은 모두 닫았다.
- 일반 성공 작업당 메인 칸 전달은 기존 두 번에서 한 번으로 줄어든다. 질문이나 시작 실패는 예외로 바로 전달한다.
- 독립 검토에서 발견한 확인 칸의 질문 뒤 최종 보고 누락과 질문 단어·URL의 잘못된 분류를 회귀 시험으로 고쳤다.
- 후속 요청에 따라 게시 명령이 첫 명령일 때만 종료 상태 출력 한 줄을 뒤에 허용했다. 기존 답글 명령도 같은 규칙을 적용한다. 수정 전 두 실패를 확인했고, 독립 검토의 파이프·백그라운드 명령과 실패 상태 반례도 실패 시험 뒤 고쳤다.
- 마지막 시험은 전달 14개와 부름 55개, 합계 69개 및 두 hook의 자체 시험을 통과했다.
