# 확인 세션의 권한 분류와 결과 전달

요청 범위는 확인 실행 환경의 사전 분류와 권한 차단 결과 보존이다. 별도 실행기는 만들지 않는다.

## 근거와 선택

11월 14~15일의 실제 실패를 대조했다. 브라우저 정책 거부, 시험 내부 ps 실행 거부, 중첩 sandbox, 개인 crontab, app-server 권한 거부가 있었다. 단독 ps 조회와 일반 API 조회를 같은 이유로 옮기지 않는다. 공통 안전 훅은 도구를 바꿔도 해결된다는 근거가 없으므로 유지한다. 오류 원문이 없는 소켓·launchctl 가정은 사전 규칙에 넣지 않는다.

지시문과 지정된 시험 파일을 읽는 공통 분류기를 쓴다. 확인 대상 파일은 실행하지 않는다. 확인 폴더의 쓰기 금지와 안전 훅을 유지한다. 지정 스크립트에서 프로세스 실행을 찾았지만 변수 인자 등으로 실행 명령을 읽을 수 없으면 Claude로 보낸다. 일반 조회나 실행 근거가 없는 요구는 Codex를 유지한다. 프로세스 실행 명령을 읽지 못한 경우는 실제 차단이 확인됐다는 뜻으로 보고하지 않는다.

보완 검토에서 변수 인자의 subprocess가 기존 app-server 차단을 놓치는 것을 재현했다. subprocess의 import 별칭과 키워드 인자, os.exec·spawn·system, asyncio 실행과 셸의 동적 실행도 같은 기준으로 다룬다. 개인 경로를 저장하는 차단 이력 목록은 추가하지 않는다. 파일 이름이나 위치가 바뀌어도 실행 근거로 판단한다.

## 작업 순서

1. 실제 실패와 일반 조회를 나누는 시험, 수동·자동 진입점 시험, 결과 전달 시험을 먼저 추가하고 실패를 기록한다.
2. 공통 분류기를 두 진입점에 연결한다. 기존 Claude 명시 선택을 보존한다.
3. TASK_CHECK의 unknown을 유지하며 blocked_reason, blocked_command, retry_target을 추가한다. 실제 코드 실패가 섞이면 fail을 보존한다.
4. 자동 전달·작업 원장에 권한 차단 정보를 남긴다. 자동 재시도나 정책 우회는 추가하지 않는다.
5. 관련 회귀 시험과 전체 로컬 pre-push를 실행하고 새 검토자가 변경을 검토한다. PR은 Draft로 남긴다.

## 검증

브라우저 명령, ps를 실행하는 지정 시험, sandbox/crontab/app-server 요구는 Claude를 고른다. 일반 pytest, 네트워크·GCP 조회, 단독 ps·launchctl 조회는 Codex를 고른다. 다섯 유형의 결과는 원문 명령과 재시도 대상이 리드에게 전달된다. 권한 차단만 있으면 unknown이고, 별도 코드 결함이 있으면 fail을 그대로 보존한다. 코드 인용과 잘못된 메타데이터는 차단 결과로 읽지 않는다.

적용은 머지 후 기존 소스 체크아웃 갱신으로 한다. 새 서비스나 재시작은 필요하지 않다. 되돌리기는 변경 커밋의 revert PR로 한다.
