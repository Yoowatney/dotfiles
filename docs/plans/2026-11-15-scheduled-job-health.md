# 정기 작업 연속 실패 알림 구현 계획

크기: L. 별도 worktree에서 구현하며 설치와 재시작은 검토 후 수행한다.

## 설계

정기 실행 plist의 명령을 래퍼로 감싸고 원래 일정·환경·출력 경로·종료 코드를 유지한다. KeepAlive 서비스는 제외한다. 각 실행의 종료 코드와 이번 실행이 추가한 명시적인 건너뜀 로그만 판정한다. 정상 무작업은 성공이다. 로그로 구분할 수 없는 건너뜀은 추측하지 않고 목록에 표시한다.

잡별 상태를 잠금과 원자적 교체로 저장한다. 실패와 건너뜀을 합쳐 연속 두 번이면 기존 메인 알림함에 고정된 사건 ID로 기록한다. 같은 장애에서는 추가 알림을 만들지 않는다. 성공하면 다음 장애를 새로 센다. 알림함이 잠겼으면 결과와 미전달 알림을 보존하고 다음 명령 실행 전에 재시도한다. 중단된 실행은 다음 시작 시 한 번만 실패로 센다.

설치 도구는 기본적으로 목록과 근거만 출력한다. 명시적인 적용 옵션에서 원래 plist와 심볼릭 링크를 백업하고 래퍼를 연결한다. 복구는 원래 내용을 되돌린다. launchctl 재시작 명령을 출력하며 자체 실행하지 않는다. 작업 내용과 원문 로그는 공개 저장소나 알림에 복사하지 않는다.

## 구현 순서와 검증

1. 실제 자식 프로세스와 임시 알림함을 사용하는 회귀 시험을 먼저 실행해 실패를 확인한다.
2. 결과 기록·연속 횟수·중복 방지·전달 재시도를 구현한다.
3. 임시 LaunchAgents를 사용하는 설치·복구 시험을 먼저 실행한 뒤 설치 도구를 구현한다.
4. 기존 알림함 시험과 새 시험을 함께 실행하고 별도 검토를 요청한다.
5. 한 번 push하여 Draft PR을 만들고 설치·복구 명령과 제한을 보고한다. 실환경에는 적용하지 않는다.
