# 대화 용량과 GitHub 사용량 관측

메인 세션이 새로 시작할 때 보이는 대화 글자 수를 큰 순서대로 기록한다.
GitHub 호출 한도는 적은 조회로 감시하고, 호출 출처는 추정치임을 명시한다.

표준 라이브러리만 쓰는 모듈 하나가 로컬 대화 기록을 읽는다. 기존 인수인계
훅이 두 대화형 런타임의 세션 전환을 기록한다. 기존 분 단위 감시 작업에
5분 간격 제한을 둔 한도 조회를 붙인다. 새 데몬, 인증 도구, 토큰 계측,
HTTP 추적, 배포는 추가하지 않는다.

## 제약

- 집계 수와 식별자만 저장한다. 대화 본문, 명령, 인증 정보는 저장하지 않는다.
- 숨겨진 문맥은 글자 수에서 제외한다. 글자 수를 토큰 추정치로 다루지 않는다.
- 보이는 gh 명령 실행 횟수를 센다. HTTP 요청 횟수를 세는 것은 아니다.
  백그라운드 작업, Codex exec·Claude REPL 스크립트, 다른 호스트의 호출은
  출처 집계에서 빠진다. 해석하지 않은 스크립트 호출은 별도로 세되, 그 안에
  gh가 있다고 단정하지 않는다. 각 경고에 미계측 범위와 읽은 기록 범위를 적는다.
- 기존 인수인계 내용을 보존한다. 큰 출처부터 줄이라는 짧은 안내만 덧붙인다.
  사용자 글, 안전 지시, 도구 결과를 자동으로 버리지 않는다.
- 여러 프로세스를 합쳐 5분에 한 번만 한도를 조회한다. 실패한 조회도 간격에
  포함한다. 남은 비율이 20% 아래면 자원과 초기화 시각별로 한 번 경고한다.
  전송 실패는 로컬에서 재시도한다.
- CI·배포 감시, 동기화 인증, 보고 검증기는 바꾸지 않는다.
- 이번 작업은 PR과 독립 Claude 검토까지다. 설치와 병합은 하지 않는다.

## 구현 단계 1: 대화 집계와 세션 시작 연결

두 대화 기록 형식, 중복 기록, 잘못된 줄, 본문 비저장, 실제 인수인계의 시작과
초기화 전환, 중첩 세션 제외를 검증하는 실패 테스트부터 만든다. 읽는 양을
제한해 집계하고, 큰 출처부터 줄이라는 안내를 붙인다. 새 테스트와 기존
인수인계 테스트가 모두 통과해야 한다. 기존 인수인계가 남고, 각 세션 시작을
한 번씩 기록하는지 확인한다.

## 구현 단계 2: 조회를 적게 쓰는 한도 감시

5분 간격, 프로세스 간 중복 실행 차단, 조회 실패, 자원별 경계값, 초기화 시각별
중복 알림 차단, 전송 실패 재시도, 보이는 명령의 출처 집계를 실패 테스트로
먼저 검증한다. 기존 분 단위 감시에 연결하고 새 테스트와 workers-watch 자체
검사를 실행한다. 각 간격에 GET /rate_limit이 한 번만 나가는지 확인한다.
실패한 응답을 잔여 한도 0으로 표시하거나 비밀값을 저장해서는 안 된다.

## 검증과 검토

관련 회귀 테스트, 컴파일·셸 검사, 실제 로컬 대화 형식을 쓰는 격리 시험을
실행한다. 커밋하고 한 번 푸시해 PR을 연 뒤 정확한 변경 범위와 근거를 독립 Claude
검토에 넘긴다. 중요한 지적은 실패하는 회귀 테스트부터 추가해 고친다.
배포는 별도로 검토된 병합 절차에 맡긴다.

## 검토할 점

1. 런타임 전환과 중첩 세션의 시작 식별, 수동 초기화와 자동 초기화의 구분.
2. 잘못되거나 큰 대화 기록과 한도 응답의 처리, 원문 유출 여부.
3. 중복·동시 실행과 한도 초기화 전후의 전송 실패.
4. 출처 추정의 한계 표시. gh 실행 횟수를 소비한 요청 수와 같다고 하지 않기.
5. 대화 내용의 자동 삭제와 제외된 도구 변경이 없는지 확인.

## 진행 기록

- 보이는 글자 수와 gh 명령 횟수만 세는 방식으로 정했다.
- 기준 상태와 실패·통과 테스트의 근거는 저장소 밖에 보관한다.
