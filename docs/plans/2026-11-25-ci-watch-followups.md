# CI 감시 후속 보강 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 반복 조회를 줄이고, 같은 실행의 감시 주체와 마지막 결과를 찾을 수 있게 한다.

**Architecture:** 기존 CLI와 파일 잠금을 유지한다. 감시 기록은 잠금과 같은 키로 원자적으로 저장하며, 상태 조회는 실제 잠금 여부를 함께 읽는다. 전역 설정이나 인증은 바꾸지 않는다.

**Tech Stack:** Python 표준 라이브러리, POSIX flock, GitHub CLI.

**Spec:** 이 문서의 범위와 접근 방식.

## 범위와 접근 방식

- PR checks의 기본 10초 조회는 60초 이상으로 제한한다. 실행 감시의 기존 60초 간격은 유지한다.
- 잠금만 기록하는 방식은 소유자와 결과를 찾을 수 없다. 별도 데몬 방식은 수명 관리가 늘어난다. 기존 CLI에 상태 조회와 원자적 메타데이터 기록을 더한다.
- 래퍼가 강제 종료되어도 실행 중인 gh가 잠금을 유지한다. 이때 PID를 알려주되 수집하지 못한 종료값은 알 수 없음으로 남긴다.
- 실행 감시는 기존 호스트 역할과 호스트 표식이 맞는 세션 호스트에서만 허용한다. 로컬 잠금이며 별도 분산 서비스는 추가하지 않는다. PR checks의 기기 간 중복은 이 제한의 범위 밖이다.
- 검사 진입점보다 먼저 실행되는 페이지 요청 가드도 CI 경로에 넣는다.

## Global Constraints

- 기존 훅, 제한 시간, 동시 실행 수를 완화하지 않는다.
- 실제 Actions 실행, 인증 전환, 서버 설정 변경은 하지 않는다.
- 상태 조회는 gh나 네트워크를 호출하지 않는다.

## Review Focus

- 래퍼 강제 종료 뒤 실행 중인 gh의 잠금과 PID를 확인한다.
- 잠금은 풀렸지만 결과가 없는 경우 성공으로 해석하지 않는다.
- 실패 종료값과 gh 시작 실패를 저장한다.
- 상태가 없거나 깨져도 상태 조회가 감시를 새로 시작하지 않는다.
- 명령 감싸기와 간격 옵션의 여러 표기에서 제한이 유지된다.

## Task 1: 감시 진입점과 상태 기록 보강

1. 상태 조회, 실패 결과, 래퍼 종료, 손상된 기록의 CLI 시험을 추가하고 실패를 확인한다.
2. `ci-watch.py --status --repo OWNER/REPO RUN_ID`를 구현한다. JSON에 `active`, `wrapper_pid`, `gh_pid`, `returncode`, `conclusion`을 제공한다.
3. PR checks의 기본·짧은 간격 거부와 60초 이상 허용 시험을 먼저 추가한 뒤 공용 가드를 수정한다.
4. 호스트 역할 조사 결과를 바탕으로 기기 간 중복 대책을 시험한다. 바꾸지 않는 부분은 이유와 근거를 기록한다.
5. CI 경로 필터를 수정하고 경로 매칭을 직접 확인한다.
6. 관련 전체 시험, 독립 Claude 리뷰, 정상 pre-push, PR 검사, 머지 뒤 설치 상태를 확인한다.
